# Data Model

> Part of the EchoGrid docs. See also [Architecture](architecture.md), [Layers](layers.md), [Simulation pipeline](simulation-pipeline.md), [Modules reference](modules-reference.md). EchoGrid outputs are **SYNTHETIC** — generated by an LLM-assisted simulator, not real polls or predictions.

This document describes the data contracts defined in `src/schemas.py` and the deterministic-randomness helpers in `src/utils.py`. Everything below is grounded in the actual source; no fields are invented.

## Base model: `EchoGridModel`

Every schema in the project inherits from `EchoGridModel`, a Pydantic v2 `BaseModel` configured with `extra="forbid"`.

```python
class EchoGridModel(BaseModel):
    model_config = ConfigDict(extra="forbid")
```

**Why strict contracts matter.** `extra="forbid"` rejects any field that is not declared on the model. Because EchoGrid feeds LLM output back into the pipeline, an LLM that hallucinates an extra key, misspells a field, or drifts from the schema will fail validation loudly at the boundary rather than silently corrupting downstream rounds. Combined with the per-field range and length constraints below, this turns every LLM response into a verified contract: a value out of range (e.g. an emotion score of `150`) or a malformed payload is caught immediately, keeping synthetic results internally consistent and reproducible.

## Reaction models

### `Emotions`
Five `0–100` integer scores. Computed property `average` returns the mean of all five.

| Field | Type | Constraint |
|-------|------|------------|
| `anger` | `int` | `0–100` |
| `fear` | `int` | `0–100` |
| `hope` | `int` | `0–100` |
| `distrust` | `int` | `0–100` |
| `indifference` | `int` | `0–100` |

```python
@property
def average(self) -> float:  # mean of anger, fear, hope, distrust, indifference
    return (self.anger + self.fear + self.hope + self.distrust + self.indifference) / 5
```

### `EmotionShift`
Same five dimensions as `Emotions` but signed deltas in range `-100–100`: `anger`, `fear`, `hope`, `distrust`, `indifference`.

## Deterministic randomness (`src/utils.py`)

Shared helpers for reproducible randomness and value normalization.

| Function | Signature | Behavior |
|----------|-----------|----------|
| `clamp` | `clamp(value, minimum=0, maximum=100) -> int` | Rounds `value` and clamps it into `[minimum, maximum]`, returning an `int`. Used to keep scores inside their `0–100` schema bounds. |
| `stable_seed` | `stable_seed(*parts) -> int` | Joins all `parts` with `"::"`, takes the SHA-256 hex digest, and returns the first 16 hex chars as an integer. |
| `seeded_rng` | `seeded_rng(*parts) -> random.Random` | Returns a `random.Random` seeded with `stable_seed(*parts)`. |
| `weighted_choice` | `weighted_choice(rng, choices) -> T` | Selects one value from `Sequence[tuple[T, float]]` by cumulative-weight sampling. Raises `ValueError` if total weight `<= 0`; falls back to the last element to guard floating-point edge cases. |

**How `stable_seed` gives reproducibility.** A normal RNG seeded once produces a single stream — re-ordering or parallelizing work changes which value any given entity receives. `stable_seed` instead derives a seed *from the identity of the thing being generated* (e.g. a population seed plus an agent id) via a content hash. The same inputs always hash to the same integer, so `seeded_rng(seed, agent_id)` yields the same `random.Random` stream every run, independent of execution order or thread count. This makes population generation and weighted sampling fully reproducible and order-independent — re-running with the same `PopulationConfig.seed` reproduces the identical synthetic society, and parallel workers (`SimulationConfig.max_workers`) cannot perturb results.
